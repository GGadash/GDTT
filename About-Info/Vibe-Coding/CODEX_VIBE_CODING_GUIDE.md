# Codex Vibe-Coding Guide

Treat Codex as a repository-aware engineering collaborator. The best prompts describe one
goal, preserved behavior, affected boundary, examples, and verification—not an entire
rebuild. Ask it to read `AGENTS.md` and handoff files, inspect first, work in the smallest
module set, test, and leave the repository resumable.

Use `MODIFICATION_PROMPTS.md` for small changes, bugs, new features, UI-only work,
transformation/averaging/import/export changes, refactoring, performance, packaging, and
interrupted sessions. For long work, request a documented checkpoint before expanding
scope. Chat history is helpful context but never the source of truth.
