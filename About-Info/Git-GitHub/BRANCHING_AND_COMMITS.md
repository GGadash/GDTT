# Branching and Commits

`main` represents working, tested, documented checkpoints. Use short-lived names such as
`feature/file-profiling`, `fix/csv-true-null`, `refactor/export-engine`, or `release/v0.2.0`.

Keep commits coherent and use messages such as:

- `feat: add configurable local day start`
- `fix: preserve true nulls in CSV output`
- `test: add gap reconstruction regression fixture`
- `docs: update phase two handoff`

Early solo work may be committed directly to `main` only when Akila DJ deliberately asks.
Automatic commit remains disabled.
